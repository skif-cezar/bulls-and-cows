# DESIGN — Bulls and Cows

Документ описывает, как устроено игровое ядро: какие структуры данных выбраны, как работают ключевые алгоритмы,
какова их сложность и какие принципы чистого кода применены (с конкретными файлами и функциями).

## 0. Слои проекта

```
src/
├── types/   типы предметной области и UI (никакой логики)
├── core/    чистые функции: генерация, валидация, сравнение, подсчёт
├── state/   чистые переходы состояния игры: (state, ввод) -> новое состояние
├── utils/   утилиты: мемоизация, setInterval, получение длин для выбранной системы счисления, localStorage
└── ui/      DOM-компоненты и контроллер экранов
```

Правило зависимостей: `ui → state, core, types`; `state → core, types`; `core → types`.
Ядро (`core/`, `state/`) ничего не знает о DOM, `window`, `localStorage`, времени и `Math.random` — всё это
передаётся снаружи аргументами.

Архитектурный приём — **«функциональное ядро, императивная оболочка»**: вся логика — чистые функции.
Контроллер `ui/render.ts` лишь связывает state, таймер и DOM.

## 1. Структуры данных и алгоритмы

### 1.1 Состояние игры

`GameState` (`types/game.types.ts`) — неизменяемая запись (все поля `readonly`):

| Поле             | Тип                  | Зачем                                                   |
| ---------------- | -------------------- | ------------------------------------------------------- |
| `secret`         | `string`             | загаданное число                                        |
| `settings`       | `{ length, base }`   | система счисленияи длина символов, которые выбрал игрок |
| `history`        | `HistoryEntry[]`     | история попыток по порядку                              |
| `status`         | `'playing' \| 'won'` | статус игры                                             |
| `elapsedSeconds` | `number`             | время — тоже часть состояния                            |

Почему так:

- **Одна запись = один источник истины.** Любое действие — это функция `GameState -> GameState`
  (`addAttemptToState`, `setGameStatus`, `tick`, `processGuess` в `state/state.ts`).
- **Неизменяемость через копирование верхнего уровня** (`{ ...state, history: [...state.history, entry] }`).
  Старое состояние остаётся нетронутым, а неизменившиеся части (например, прежние записи истории) переиспользуются
  по ссылке — это проверяет тест «сохраняет старые записи» (`toBe`).

### 1.2 История попыток

`HistoryEntry[]`, где `HistoryEntry = { guess, bulls, cows }`, — добавление только в конец.

- Порядок важен (список показывается в порядке попыток).
- Размер истории мал (десятки записей), поэтому добавление копированием `O(n)` и проверка повтора через `some`
  (`isAlreadyGuessed`, `O(n·k)`) не заметны. `Set` для O(1)-проверки повторов потребовал бы хранить вторую
  структуру рядом с массивом и копировать её при каждом ходе — сложность без выигрыша.
- Хранится уже **вычисленный** результат (`bulls`, `cows`), поэтому отрисовка истории не пересчитывает ничего.

### 1.3 Прочие структуры

- `BASE_ALPHABETS: Readonly<Record<Base, string>>` (`core/constants.ts`) — замороженная таблица алфавитов; единственный
  источник правды (по ней считаются допустимые длины, валидация, генерация). `getAlphabet` использует `Object.hasOwn`,
  чтобы значения вроде `'constructor'` не принимались за систему счисления.
- `includes` внутри `createDigitValidator` — проверка «символ из алфавита» за O(1).
- Таблица рекордов — `RecordItem[]`, отсортированная «лучшие первыми» (меньше попыток, затем меньше времени),
  не более 10 записей (`insertAndSortRecord` в `core/records.ts`). Сериализация — JSON в `localStorage`, но только на границе; читаемые данные проверяются (`getRecords`), поэтому испорченное хранилище не ломает игру.

### 1.4 Алгоритм `evaluateGuess(secret, guess)`

`core/evaluateGuess.ts`. Бык — верная цифра на верной позиции; корова — верная цифра на другой позиции.

1. Привести обе строки к нижнему регистру и разбить на символы (hex не зависит от регистра).
2. Если длины не равны — это ошибка программиста (до функции такой ввод не должен дойти), бросить исключение.
3. `bulls` = число позиций `index`, где `char === secretChars[index]`.
4. `common` = сколько символов попытки вообще встречаются в секрете (проверка по `Set` символов секрета).
5. `cows = common - bulls`.

Почему это верно: цифры в секрете и в попытке **уникальны** (гарантируют `generateSecret` и `isValidGuess`).
Поэтому каждая «общая» цифра — либо бык (на своём месте), либо корова (не на своём), и ничто не считается дважды.
Пример: секрет `1234`, попытка `1325` → `bulls = 1` (цифра `1`), `common = 3` (`1`, `3`, `2`), `cows = 3 - 1 = 2`.
Если бы в строках были повторы, формула давала бы завышение.

### 1.5 Алгоритм `countPossibleSecrets(length, base)`

`core/countPossibleSecrets.ts` + `core/combinatorics.ts`. Секрет — **упорядоченная** выборка `k` **различных** цифр
из алфавита размера `n`, то есть число размещений без повторений:

```
P(n, k) = n! / (n − k)! = n · (n−1) · … · (n−k+1)
```

Реализация — рекурсия по определению с мемоизацией:

```
P(n, 0) = 1
P(n, k) = n · P(n − 1, k − 1)        (0 < k ≤ n)
P(n, k) = 0                          (k > n или k < 0)
```

Примеры: `bin`, длина 2 → 2; `dec`, длина 4 → 5040; `dec`, длина 6 → 151 200; `hex`, длина 6 → 5 765 760.
Ведущие нули разрешены (`0123` — допустимый секрет), поэтому формула «первую цифру нельзя взять нулём» не применяется.
Значение показывается на стартовом экране как «Unique combinations».

## 2. Сложность

Обозначения: `k` — длина секрета (2…6), `n` — размер алфавита (2…16), `m` — длина строки попытки.
Из-за малых констант всё работает мгновенно; ниже — асимптотика, чтобы было видно, как поведёт себя код при росте.

| Функция                | Время                                 | Память     |
| ---------------------- | ------------------------------------- | ---------- |
| `generateSecret`       | `O(k · n)`                            | `O(k · n)` |
| `evaluateGuess`        | `O(m)`                                | `O(m)`     |
| `isValidGuess`         | `O(n + m)`                            | `O(n + m)` |
| `countPossibleSecrets` | `O(k)` первый вызов, `O(1)` повторный | `O(k)` кэш |

**`generateSecret`** (`core/generateSecret.ts`). Рекурсия `pickDistinct` делает `k` шагов. На каждом шаге выбирается
случайный индекс (`O(1)`) и строится новый пул без выбранной цифры (`slice` + spread, `O(n)`), плюс сборка результата
spread-ом (`O(k)`). Итого `k · (n + k) = O(k · n)`, так как `k ≤ n`. Память такая же: рекурсия держит `k` копий пула.
Классический Fisher–Yates «на месте» дал бы `O(n + k)`, но он мутирует массив; здесь сознательно выбрана неизменяемость,
а при `n ≤ 16`, `k ≤ 6` разница — десятки операций. Уникальность цифр достигается по построению: выбранная цифра
удаляется из пула, повтор невозможен.

**`evaluateGuess`** (`core/evaluateGuess.ts`). Разбиение строк — `O(m)`, построение `Set` из секрета — `O(m)`, подсчёт быков —
один проход `O(m)`, подсчёт общих цифр — один проход с `Set.has` за `O(1)`, итого `O(m)`. Раньше проверка делалась через
`secretChars.includes(char)` внутри `filter` — это `O(m²)`; замена массива на `Set` убрала квадратичную часть.

**`isValidGuess`** (`core/isValidGuess.ts`). Правила применяются по очереди и обрываются на первой ошибке.
Длина — `O(1)`. Проверка алфавита: построение валидатора (`Set` из `n` символов алфавита) — `O(n)`, затем `m` проверок по `O(1)`,
итого `O(n + m)`. Уникальность — построение `Set` из `m` символов, `O(m)`. Сумма — `O(n + m)`; на практике `m = k` и `n ≤ 16`.

**`countPossibleSecrets`** (`core/countPossibleSecrets.ts`, `core/combinatorics.ts`). Поиск алфавита и проверки — `O(1)`.
`getPermutations(k, n)` рекурсивно спускается на глубину `k`, на каждом уровне — одно умножение и обращение к `Map`:
`O(k)` при первом вызове. Результат каждого уровня кэшируется по ключу `k_n`, поэтому повторный вызов (например, при
каждом переключении селекта на стартовом экране) — `O(1)`. Кэш содержит не более `k_max · n_max` записей — ограничен
константой. Без мемоизации сложность была бы той же `O(k)` — мемоизация здесь экономит повторные спуски, а не меняет класс.

## 3. Принципы чистого кода (Clean Code) — где и как применены

**Одна ответственность (SRP).**

- `core/records.ts` — только чистая логика таблицы рекордов (`getRecords`, `addRecord`, `isValidRecord`);
- `utils/gameTimer.ts` (`startGameTimer`) только вызывает колбэк раз в секунду; время игры хранится в состоянии (`tick` в `state/state.ts`).
- Каждый UI-компонент (`ui/components/game/*`) строит один фрагмент интерфейса.

**Функции маленькие и делают одно дело.** `isValidGuess` — это композиция трёх правил `lengthRule`, `alphabetRule`,
`uniquenessRule` (`core/isValidGuess.ts`); `processGuess` (`state/state.ts`) читается как сценарий: проверить конец игры → нормализовать ввод → валидировать → проверить повтор → оценить → добавить в историю → проверить победу.

**Осмысленные имена.** `addAttemptToState`, `renderStartScreen`, `getRecords`, `startGameTimer`, `pickDistinct`, `getAvailableLengthOptions`:
имя говорит, что делает функция, без комментария.

**DRY.**

- Алфавиты заданы один раз (`BASE_ALPHABETS`);
- Диапазон длин `2…6` — константы `MIN_SECRET_LENGTH` / `MAX_SECRET_LENGTH` (`core/constants.ts`), а не «магические числа» в проверках.

**Внедрение зависимостей (DIP) и чистота.** Источник случайности — аргумент `random` в `generateSecret` (`Math.random` передаётся только в `ui/render.ts`);
`id` и дата — аргументы `addRecord` (`core/records.ts`).

**Разделение команд и запросов (CQS).** Все функции состояния — запросы: возвращают новое значение и ничего не меняют
(`addAttemptToState`, `setGameStatus`, `tick`).

**Обработка ошибок: исключения — для багов, значения — для ошибок пользователя.** Неверный ввод игрока — обычное значение
(`ValidationResult`, `GuessProcessResult` в `types/game.types.ts`), без `try/catch` в UI. Нарушенное предусловие
(неподдерживаемая система, неверная длина) — `throw` в `generateSecret`, `countPossibleSecrets`, `evaluateGuess`.
Повреждённые данные из `localStorage` не приводят к падению (`addRecord`, `getRecords`).

**Отсутствие мёртвого кода и шума (YAGNI).** Удалены неиспользуемый статус `'lost'`, закомментированный `closeModal`
и недостижимая ветка `Array.isArray(bodyContent)` в `ui/components/modal/modal.ts`, лишние `console.log`,
служебные `console.warn` при валидации.

**Комментарии объясняют «почему».** Предусловие уникальности цифр в `evaluateGuess`, причина `Math.min` в `pickDistinct`,
причина `Object.hasOwn` в `getAlphabet`.

**Тесты как документация (F.I.R.S.T.).** Тесты ядра быстрые, независимые и повторяемые: нет DOM, времени и случайности
(`*.test.ts` рядом с кодом). Каждое поведение описано отдельным `it` на русском.
